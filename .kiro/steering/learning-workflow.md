# 学习与笔记协作方式

用户的学习和写作风格是：**先建立骨架，再逐步展开，最后填充细节**。

## 笔记结构

```
notes/skeleton/    骨架层：一页纸，只有结构，用于导航
notes/deep-dive/   细节层：展开某个具体点
```

## 协作原则

**探索阶段**
- 用户问"给我一个大致的骨架/枝干"时，输出极简结构，不要急着填细节
- 确认骨架方向对了，再展开
- 每次只深入一个层次，不要一次把所有细节都倒出来

**记录阶段**
- 新主题先写 `skeleton/` 文件（一页纸），再写 `deep-dive/` 文件
- 骨架文件末尾用 `→ 见 deep-dive/xxx.md` 指向细节
- 笔记写入文件，不要只输出到聊天框（除非用户明确说"直接输出"）

**整理阶段**
- 重组笔记前先 `git commit` 存档
- 骨架和细节分离，不混在同一个文件
- 定期检查骨架文件是否还能在 30 秒内定位到任何主题

## 写作协作

- 用户说"写一篇文章"时：以 skeleton 文件为大纲，deep-dive 文件为素材库
- 文章输出到聊天框（用户手动复制），同时创建空文件占位
- 深度解析类文章要结合源码，给出具体的文件路径和行号
