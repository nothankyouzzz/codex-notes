# 学习 + 笔记编排 Workflow

## 学习流程

```
1. 扫描项目结构          → 建立整体认知，识别主要模块
2. 确定关注点            → 聚焦核心主题（如 agent loop）
3. 读骨架代码            → 找到最小可理解单元
4. 逐层展开              → 从最小骨架出发，每次只加一层细节
5. 边学边记              → 每个阶段产出一篇笔记，先骨架后细节
6. 定期整理              → git 存档，然后重组结构
```

## 笔记结构原则

```
skeleton/    一页纸，只有结构，回答"是什么、有哪些、在哪里"
deep-dive/   展开某个具体点，可以很长，但只聚焦一个主题
```

## 具体操作

- 新主题：先在 `skeleton/` 写一页骨架，确认结构对了再展开
- 展开细节：在 `deep-dive/` 新建文件，骨架文件末尾加 `→ 见 deep-dive/xxx.md`
- 写文章：以 skeleton 文件为大纲，deep-dive 文件为素材库
- 存档：`git commit` 在重组前做，保留历史快照

## 关键原则

- 骨架和细节分离，不混在同一个文件
- 骨架文件是导航地图，不是内容容器
- 先确认骨架正确，再填充细节（避免在错误方向上浪费精力）
- 笔记是写给未来的自己的，骨架层要能在 30 秒内定位到任何主题
